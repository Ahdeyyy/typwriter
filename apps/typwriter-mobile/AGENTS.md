# typwriter-mobile

The standalone Android Typst editor. Tauri 2 + SvelteKit (static adapter, SPA fallback) + a Rust core wrapping the Typst compiler. It shares the Typwriter *design system* with `apps/typwriter-desktop` (CSS tokens, Tailwind 4, shadcn-svelte, hugeicons) but **no code** — treat it as an independent app.

Android is the only shipping target. `bun tauri dev` opens a desktop window purely as a fast dev loop; nothing may depend on desktop-only behaviour.

See `README.md` for the dev loop, the `adjustResize` manifest note, and the app-icon rule (`bun run icons` must run *after* `android init`, or the APK ships the default Tauri icon; the adaptive icon comes from `src-tauri/android-icon/`, not `app-icon.png`).

## Conventions

- camelCase for variables/functions, PascalCase for classes. `bun` for the frontend, `cargo` for Rust.
- SvelteKit 3, Vite 8, TypeScript 6 (not 7: SvelteKit 3, svelte-check and typescript-eslint don't support it yet), ESLint 10. Needs Node 22.17+.
- There is no `svelte.config.js`: the adapter, `preprocess` and `version.pollInterval: 0` are passed to `sveltekit({...})` in `vite.config.ts`; `eslint.config.js` reads them back through `@sveltejs/load-config`.
- `$lib` no longer exists. Import shared code through the `#lib` subpath import (`package.json` `imports`) with the file's real extension: `#lib/stores/editor.svelte.ts`, `#lib/components/ui/button/index.ts`, `#lib/utils.ts`. Bun tests mock modules by that exact specifier (`mock.module('#lib/ipc/commands.ts', ...)`). `components.json` uses `#lib` too.
- `tsconfig.json` sets `types: ["$app/types", "bun"]`: TypeScript 6 no longer loads @types packages implicitly, and SvelteKit requires `$app/types` in any `types` list.
- Validate Rust with `cargo check` in `src-tauri/` (`RUST_MIN_STACK=8388608` on Windows). Full builds are slow and can OOM.
- Every Svelte store is a class with a singleton export — module-level `$state` exports lose reactivity.
- `src/lib/ipc/commands.ts` is the **only** place `invoke` is called; `types.ts` mirrors the Rust contract.

## Hard constraints

These are the ones that cost real debugging time. Violating any of them breaks the app on device while looking fine in the desktop dev window.

- **Every Tauri command is `async`.** Sync commands and `tauri-plugin-android-fs` calls run on the main thread and stall the whole app. Fonts load in a background task; setup must never block.
- **No live-typing preview.** Per-keystroke compile froze the app on device. Compiles are driven by idle-save, blur, and view toggles — disk is the source of truth, not the in-memory buffer.
- **Keyboard avoidance uses `--app-height` from `visualViewport`**, not `svh`/`dvh`. Anchor the shell to the layout viewport; never translate by `vv.offsetTop`. Caret re-scroll lives in a CodeMirror `ResizeObserver` plugin.
- **Never scroll to the caret during a range selection or an active touch gesture.** It's a feedback loop that drags the cursor away from the user's finger. See `src/lib/editor/caret-visibility.ts`.
- **No inline `<style>` in `app.html`.** Tauri nonces inline styles into the CSP's `style-src`, which makes the WebView ignore `'unsafe-inline'` — and CodeMirror's runtime `<style>` elements carry no nonce. The editor then renders unhighlighted and can't scroll, on device only. Pre-paint CSS goes in `static/boot.css`; `src/app-html.test.ts` guards it.
- **Every modal answers the back gesture.** Overlays go through `app.openOverlay`; any other dialog, drawer, or dropdown registers with `dismissOnBack` (`lib/back-dismiss.svelte.ts`), or back skips it and leaves the screen.
- **Modal body locks must always be released.** A stranded `pointer-events: none` on `<body>` kills every tap in the app. All locking goes through `src/lib/body-lock.ts`.
- **Storage is split.** `std::fs` only reaches the app's own directories; SAF-picked folders (folder workspaces, the app-wide fonts folder, standalone documents) go through `tauri-plugin-android-fs`. There are no runtime storage permissions to request, and there must not be: `MANAGE_EXTERNAL_STORAGE` would block a Google Play release.
- **Folder syncing is a per-workspace choice and runs on a mirror.** There is no global switch: each workspace is in app storage or syncs with a folder, and every way into syncing (the New workspace switch, Open folder, "Sync with a folder…") shows `sync-tradeoffs.svelte` first; "Stop syncing" (`move_workspace_to_app`) brings one back. The engine (compiler, tree, exports) only sees the private mirror; `folders/sync.rs` keeps it in step with the picked folder and reports inbound changes itself (`watcher::report_external`) — the mirror gets no poll watcher. Every sync state change is emitted as `workspace:sync-status`; keep its UI small — `sync-indicator.svelte` (a dot on the phone files button, an icon in the tree footer / tablet tab strip, and a red header button only while the folder can't be reached) is on screen exactly while syncing runs; toasts are only for a first copy and for losing or regaining the folder, and they time out — every way back to the explanation opens the one `sync-details.svelte` sheet via `workspace.syncDetailsOpen` (the can't-reach toast's "Details" too). Every in-app file change goes through `WorkspaceState::mutate` — folder first, then the mirror, under one lock — or it never reaches the folder (and a pull would then undo it). Pulls into the mirror are deliberately *not* claimed as self-writes: that is how inbound changes reach the frontend. Workspaces are addressed by id (`app:<name>` / `folder:<hex>`), never by name.
- **External changes reload a clean buffer, flag a dirty one.** Never silently discard unsaved text: autosave makes "dirty" a few seconds wide, and losing what the user typed inside it is worse than showing a stale file with a warning. Reloads dispatch a *minimal* change (`lib/editor/minimal-change.ts`) — a whole-document swap collapses the caret to the top of the file.
- **Rename/move/delete return `{tree, from, to}`.** Tabs, the active buffer, the Rust main `FileId`, and persisted metadata are all keyed by path and must be remapped together.
- **Edge to edge: use `--safe-top` / `--safe-bottom` / `--safe-left` / `--safe-right`, never `env(safe-area-inset-*)`.** The app draws behind the system bars and `env()` reads 0 in many Android WebViews; `stores/system-bars.svelte.ts` fills the vars from the native plugin. The plugin measures insets *ignoring visibility*, so hiding the status bar never shifts the layout.
- **Immersive chrome hides only for the user's own scrolling.** `stores/immersive.svelte.ts` hides the phone editor's floating header, dock and the status bar (and the full-screen preview's controls) on a downward finger scroll; an upward scroll, a tap, or the top brings them back. Programmatic scrolls (caret lifting, page jumps) never hide anything, and the keyboard, an open sheet, an unanswered banner, or the "Hide controls while scrolling" setting turned off keep everything visible — the status bar is hidden in no other state. The inline title has its own setting.
- **Completions are ranked client-side.** `typst-ide` never filters by prefix, so rank *then* truncate — otherwise `#im` suggests `align, alt, arguments…` and never `image`.

## Architecture

### Rust core (`src-tauri/src/`)

- `lib.rs` — `run()` builds the app, registers the `previewimg://` scheme, and lists every command in `invoke_handler!`.
- `world.rs` — the `typst::World` + `typst_ide::IdeWorld` implementation.
- `compiler.rs` / `renderer.rs` — compile and lazy on-demand page rendering, served over `previewimg://` keyed by content fingerprint.
- `workspace.rs` — workspace IO on a local root (an app-storage workspace, or a folder workspace's mirror), path-traversal guards, and rename/move path remapping. `document.rs` handles standalone SAF source IO and a private compilation mirror; only that granted file is exposed in its tree. Do not route standalone opens through `open_workspace` or write metadata beside the source.
- `folders/` — folder workspaces: `remote.rs` (the picked folder: `SafRemote` on Android, `PathRemote` in the desktop dev loop, behind one `Remote` trait whose SAF half type-checks off Android), `sync.rs` (mirror ↔ folder: write-through; the open file checked every 1 s, the folder listed every 4 s, paused in the background; conflict check on save; status events), `registry.rs` (`<app data>/workspaces.json`: folder entries and the default location). `move_workspace_to_folder` / `move_workspace_to_app` move one workspace either way; the package store (`Typwriter/Packages`) stays in app storage.
- `document.rs` — standalone document picker/open/save, original-URI conflict checks, and the native file-open queue. Tauri's Android `RunEvent::Opened` enqueues URIs; `app:open-files` is only a wakeup. `build.rs` owns the Android file associations through `android_file_associations.rs`: the `*/*` and MIME-free content/file `VIEW` filters require a `.typ` URI suffix, and a third, path-free filter matches opaque URIs reported with `TYPST_MIME_TYPES` (octet-stream plus the Typst types). `validate_name` rejects anything that isn't `.typ`. Never add `*/*`, `text/*` or `text/plain` without a path constraint, and don't add associations in `bundle.fileAssociations`. `world.session_gate` serializes root replacement, document IO, and compilation.
- `fonts.rs` — embedded + system fonts, plus the SAF app-wide fonts folder (`pick_fonts_dir` / `clear_fonts_dir`).
- `watcher.rs` — external-change detection for the open workspace. **Polling, not inotify**: shared storage is a FUSE mount and writes reaching the lower filesystem another way (MTP, `adb push`, MediaProvider) can land without raising an event, and missing a change silently is the one failure this cannot have. A poll cannot pair the halves of a move, so an external rename arrives as a removal plus a creation. Every command that writes claims its paths on `WatcherState::self_writes` — by *state*, not a time window — or autosave polls back as an external change.
- `commands/` — `app`, `workspace`, `editor`, `compile`, `cursor`, `click`, `export`, `format`, `spell`.
- `spell.rs` — spell checking. Spelling always comes from `spellbook` with the bundled `dictionaries/en_US` (SCOWL), so it's the same on every device. `spell_check` asks the device's spellchecker service (the `spellcheck` plugin) at the same time, for grammar only — its spelling flags are dropped — and goes without grammar when there's no service, the user turned it off, or for 60 s after it fails or times out. The dictionary is parsed on first use; its suggestions are slow, so they're fetched per word (`spell_suggest`) and cached rather than sent with each check. `dictionaries/` is data with its own license: `scripts/generate-licenses.ts` lists it under `bundledData`.
- `../plugins/spellcheck/` — local Tauri plugin (Rust + Kotlin, `com.typwriter.spellcheck`) around Android's `SpellCheckerSession`. No JS commands: only `spell.rs` calls it, from Rust. One session, on its own `HandlerThread`, one request at a time; a request that times out closes the session so its late answer can't be taken for the next one's. `RESULT_ATTR_LOOKS_LIKE_GRAMMAR_ERROR` (Android 12+) becomes a `grammar` issue, so grammar comes from whatever service the keyboard ships, Gboard's included; that is all the app takes from it.
- `../plugins/system-bars/` (i.e. `src-tauri/plugins/`) — local Tauri plugin (Rust + Kotlin, `com.typwriter.systembars`): hide/show the status bar, bar icon colour from the app theme, and system-bar insets in CSS px. `gen/android` is never committed, so native code lives in a plugin crate — tauri-build links its `android/` library into every generated project. It is the app's own code: the license catalog skips path crates. The Kotlin only compiles in an Android build (`bun tauri android build` / CI); `cargo check` covers the Rust side.

### Frontend (`src/`)

- `lib/components/screens/` — `home`, `editor`, `tab-switcher`, `quick-switcher`, `settings-overlay`.
- `lib/components/` — `file-tree/` (left sheet, or docked), `preview/` (full-screen overlay, or docked), `toolbar/` (two-mode editor toolbar + completion strip, the phone dock, the tablet `tab-bar`), `diagnostics/`, `editor/`, `sidebar/`, `ui/`.
- **Phone chrome (Obsidian-style).** The editor is edge to edge: text runs under the status bar, the header is floating round buttons (`.float-btn` / `.float-pill` in `layout.css`) over a status-bar-high fade, and the file name is the editor's inline title (`editor/inline-title.ts`, a CodeMirror block widget) rather than a header label. `--editor-pad-top` keeps the first line clear of the header, and `immersive.editorObscuredTop` feeds the caret's scroll margins. Tablets keep the in-flow tab strip.
- `lib/stores/` — `app`, `workspace`, `editor`, `compile`, `settings`, `layout`, `updater`, `immersive`, `system-bars`, `spell`. Settings persistence is frontend-owned via `tauri-plugin-store`; there are no Rust settings commands.
- **Updates.** `updater` calls `check_for_update`, which reads the track's `android.json` (CI publishes it next to the APK; the nightly app is the identifier ending in `.nightly`). Installing is just opening the APK URL — never add in-app install (`REQUEST_INSTALL_PACKAGES`) without a plan for it. See README "Updates", including the Obtainium fallback.
- **Tablets.** `layout` sets `tablet` (sw600dp: the screen's smallest side ≥ 600 and the window ≥ 600 wide) and `wide` (≥ 1000px) as classes on `<html>`, backing the `tablet:` / `wide:` Tailwind variants. Tablets swap the floating header and bottom dock for a tab strip header; `wide` also docks the file tree and the preview beside the editor. Never key the layout on window *height* — the keyboard shrinks it (`adjustResize`) and the layout would flip mid-typing. A docked preview counts as "open" for `compileStore.onSaved`.
- `lib/editor/` — CodeMirror setup (`create-editor.ts`), the touch completion strip (`completion-controller.svelte.ts`, `completion-logic.ts`), keyboard/caret handling (`keyboard-visibility.svelte.ts`, `caret-visibility.ts`, `scroll-pin.ts`), and `typst-lang/`.
- `lib/editor/spellcheck/` — underlines for Typst prose. `prose.ts` turns the syntax tree into plain-text paragraphs with a map back to the source (code, math, raw, refs, links, strings and comments dropped; content blocks kept). `index.ts` checks only the paragraphs around the viewport, after the buffer has been idle, one request at a time, and caches each paragraph's answer by its text. The caret in a flagged word fills `stores/spell.svelte.ts`, and the completion strip shows that word's fixes when there's nothing to complete. It must not wait for `view.composing` to clear: Android keyboards keep the word at the caret composing for as long as the caret sits in it, so that never happens. Only the word being typed is held back (composing, and the caret hasn't moved since the edit) — a tapped word is composing too, and keeps its underline. The keyboard's own `spellcheck` attribute stays off on the editor: on a contenteditable it fights CodeMirror over the composing word.
- `lib/editor/typst-lang/` — the mobile editor themes, plus a re-export of `typst` from the `codemirror-typst` npm package. The parser itself is not in this repo: it lives in `Ahdeyyy/codemirror-typst` (checked out as `../codemirror-typst`) and is shared with desktop, so a parser fix lands there once and reaches both apps through a version bump.
- `lib/ipc/`, `lib/paths.ts`, `lib/body-lock.ts`, `lib/preview-url.ts`, `lib/actions/`, `lib/hooks/` — shared helpers.

### Build config

- `vite.config.ts` — SvelteKit's own options (see Conventions), dev server on port 1430 (desktop uses 1420). The `resolve.dedupe` list is load-bearing: two copies of `@lezer/common` collide `NodeProp` ids and highlighting silently renders as plain text. The root `package.json` `overrides` block pins the versions; check that pin before writing any CodeMirror workaround, since it caps both apps.
